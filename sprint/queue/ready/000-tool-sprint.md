title: tool 0b - built, verdict, deliver and the round check
serial: ds-tools
---
Goal: "is this folder complete", a judge verdict, a delivery into the customer repo and "did this round make one real thing" are each one command.
Scope: `tools/orders-check.mjs`, `tests/orders-check.test.mjs`, `.gitignore` (add `sprint/queue/round-state.json`).
0. `--built <id>`: prints `BUILT PASS <id>` or `BUILT FAIL <id>: <first problem>`; exit 1 on FAIL. It checks brief.json, page.html, tokens.css, `out.png` and every size in the brief at exact pixels, thumb-256.png, design-audit.json AUDIT PASS, DESIGN-REVIEW.md SHIP at 8 or more, DELIVERY.md, and, when the product folder has pictures, an `assets.json` that lists at least one used picture that exists under `assets/`. The desk's JDG list and BLD rows now use it (a folder that fails `--built` is a BLD row ending with its first problem).
1. `--verdict <id> PASS|FAIL --line "<text>"`: the line must hold the five labels BEATS, PICTURE, FACTS, FIT, LANE. It writes `designs/<id>/VERDICT.md` (first line `VERDICT: PASS` or `VERDICT: FAIL`, then the five lines, the UTC date, the number of repairs so far). PASS is refused unless `--built` PASSes.
2. `--deliver <id>` (and `--dry`, `--check`): refuses unless VERDICT is PASS. Customer folder: factory `<product folder>/covers/from-design-studio/<id>/` (the product folder is the parent of the `listing/` folder in the brief's `Facts:` path; Maxim S84), every other customer `<customer dir>/from-design-studio/<id>/`. It copies the folder's files with names `<id>-<slug>-<file>` (the id in the name lets the empire's order board see a later use by name), refuses to overwrite a different file, writes `designs/<id>/DELIVERED.json` (customer path, sha256 of each file), sets the order row to `delivered` with `delivered_path` the customer-relative folder. `--dry` prints the folder and the renamed files and writes nothing. `--check` re-hashes the customer files against `DELIVERED.json`.
3. `--round [--save]`: prints `ROUND: real yes|no | built <n> | judged <n> | delivered <n> | adopted <n> | tools <n> | unjudged-oldest <m> min | in-flight <n>` against the snapshot in `sprint/queue/round-state.json` (written only with `--save`). `real yes` needs at least one of: a new `BUILT PASS` folder, a new VERDICT, a new `DELIVERED.json`, a new `packs/donors/*/SOURCE.json`, a new `arsenal.json` tool whose test passes. Exit 1 on `real no`: that round writes no handoff commit.
Proof: tests for each flag on a fixture; `node tools/orders-check.mjs --built O-001` prints BUILT PASS or its first problem; `node tools/orders-check.mjs --deliver O-001 --dry` prints `products/book-forge-pro/book-forge-pro/covers/from-design-studio/O-001/` and the renamed files; `node tools/orders-check.mjs --round` prints a ROUND line.
Stop: M 25 min; at the budget report what landed and the next step.
